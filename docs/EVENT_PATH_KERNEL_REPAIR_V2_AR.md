# إصلاح نواة Event-Path v2

## نطاق الإصلاح

هذا الإصلاح عام ومحايد للمجال. لم تتغير تعريفات الحالات أو بيانات USGS أو عقد النقل. أصبحت `rolling_oos` العامة تستدعي predictor المجمد الذي يكتشف العلاقة الشرطية داخل train، يطبق `min_support`، ويمتنع عند غياب الدعم بدل تحويل الحالة إلى persistence fallback.

تم إبقاء التنفيذ السابق باسم `rolling_oos_legacy` لأغراض التتبع التاريخي فقط، لكن واجهة التشغيل العامة لم تعد تستخدمه.

## النتيجة الاقتصادية

أُعيد تشغيل المسار الاقتصادي الموجود في CHAOS باستخدام لوحة WDI نفسها وواجهة `rolling_oos` العامة بعد الإصلاح.

| المقياس | النتيجة |
|---|---:|
| Events | 4,780 |
| OOS predictions | 3,229 |
| Path accuracy على الصفوف المدعومة | 0.6028 |
| Majority accuracy على الصفوف نفسها | 0.4859 |
| Path coverage | 0.4717 |
| Abstention rate | 0.5283 |

لا تعني هذه الأرقام ثبوتًا سببيًا أو استقرارًا خارج العينة؛ إنها تثبت أن الإصلاح يعمل على مسار اقتصادي عام ولا يعتمد على خصائص الزلازل.

## الحكم المعماري

التحسين المطلوب لكي يتحول CHAOS من Pattern discovery إلى prediction ليس زيادة عدد المسارات، بل ضمان أن كل Path يملك تعريفًا مجمدًا، ودعمًا أدنى، وهدفًا تاليًا معلومًا، وسلوك abstention، وتقييمًا منفصلًا عن fallback.

هذه الطبقة صارت الآن في نواة المحرك ويمكن إعادة استخدامها عبر المجالات. أما الحكم العلمي على أي domain فيظل مستقلًا ويحتاج Null مناسبًا وcoverage معلنة وتكرارًا خارج المجال.
