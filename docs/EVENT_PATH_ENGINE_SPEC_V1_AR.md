# مواصفة محرك Event-Path v1

## الغرض

ينقل هذا المكوّن وحدة الاكتشاف في CHAOS من Edge منفردة إلى سلسلة قابلة لإعادة الاختبار: **Event → State → Transition → Event Window → Path → Next-State Prediction → Rolling OOS Evaluation**. النموذج محايد للمجال، بينما يحدد الـadapter معنى الحدث والقيمة والتواتر.

> النتيجة التنبؤية لا تساوي دليلًا سببيًا، ولا يسمح هذا الإصدار بترقية المرشح إلى runtime signal.

## النموذج

| الكيان | الوظيفة | متطلبات الدليل |
|---|---|---|
| `Event` | مشاهدة مرتبة زمنيًا من مصدر محدد | `source_id` و`source_ref` وSHA-256 والتواتر الأصلي |
| `State` | تصنيف الحالة المشتق من التاريخ السابق فقط | قاعدة تصنيف صريحة وحالة `insufficient_history` عند غياب السياق |
| `Transition` | انتقال بين حالتين مع lag ومقاييس المصدر والهدف | لا يوصف كعلاقة سببية تلقائيًا |
| `EventWindow` | آخر `k` أحداث قبل نقطة التنبؤ | عرض النافذة يحدد مسبقًا ويسجل في العقد |
| `Path` | تسلسل حالات وتحولات داخل النافذة | معرف ثابت ومراجع provenance |
| `Prediction` | الحالة التالية المتوقعة قبل كشف النتيجة | يحفظ `actual_state` بعد التقييم ولا يعيد تعريف المسار |
| `Outcome` | الحالة الفعلية التالية | تستخدم فقط في OOS بعد تجميد تعريف المرشح |

## المحول الأول

يستخدم `AnnualPanelAdapter` لوحة WDI السنوية الموجودة أصلًا في CHAOS، ولا يخلط التواتر السنوي مع event-native أو daily data. التجربة الأولى تستخدم `wdi__NY.GDP.MKTP.KD.ZG` كقيمة اقتصادية سنوية؛ ويمكن استبدال العمود دون تعديل نواة المحرك.

لكل كيان، تُنشأ Events من الصفوف ذات القيمة الرقمية. تُشتق الحالة من تغير الفاصل بين الأحداث وتغير `relative_increment`. إذا لم تتوافر نافذة تاريخية كافية، تكون الحالة `insufficient_history` بدل التخمين.

## الاكتشاف والتقييم

تستخدم النوافذ بعرض افتراضي قدره 3 أحداث، ويجري التنبؤ بطريقة chronological rolling OOS: يدرب المحرك على السجل المتاح حتى نقطة زمنية، يبحث عن تاريخيات مطابقة للنافذة، ثم يتنبأ بالحالة التالية قبل قراءة actual outcome. تحفظ كل تنبؤ في `PREDICTIONS.jsonl`.

تُقارن نتيجة المسار بثلاثة baselines: **persistence**، و**majority/base-rate**، و**simple recent-trend**. لا يُسمى المرشح مدعومًا لمجرد تفوقه في تشغيل واحد؛ وضع التشغيل الناتج هو `provisional` ويحتاج إلى اختبارات null وتصحيح بحث وتكرار على مجال أو مصدر مستقل.

## مخرجات التشغيل

يُشغّل النموذج بالأمر التالي من جذر المستودع:

```bash
python3 tooling/run_event_path_prototype_v1.py
```

وينتج في `experiments/event_path_prototype_v1/` ملفات `EVENTS.jsonl` و`STATES.jsonl` و`TRANSITIONS.jsonl` و`WINDOWS.jsonl` و`PATHS.jsonl` و`CANDIDATE_PATTERNS.jsonl` و`PREDICTIONS.jsonl`، إضافة إلى `RUN_SUMMARY.json` و`EXECUTION_REPORT.md`.

## حدود الإصدار

هذا الإصدار لا يدعي اكتشاف نمط زلزالي في خليج عدن؛ فلا توجد في المصدر الحالي بيانات زلزالية event-native كافية داخل المسار المختار. لذلك استُخدم dataset اقتصادي فعلي موجود في CHAOS لتطوير المحرك، بينما تبقى حالة خليج عدن seed تصميمية تحتاج مصدرًا رسميًا قابلًا لإعادة التشغيل قبل الحكم عليها. كما أن اختبار الاستقرار عبر مصادر أو مجالات مستقلة وتصحيح تعدد المسارات ما زال شرطًا لاحقًا.
