# عقد تصميم نموذج العدم الزلزالي — CHAOS P2.2.2

**الحالة:** عقد بحثي قبل التنفيذ؛ لا توجد نتيجة زلزالية جديدة في هذا المستند.  
**فرع العمل:** `p2.2.2-seismic-null-contract`  
**النطاق:** خمس نوافذ USGS ComCat، 1980–2024، الحد الأدنى للاستعلام M≥4.5، كما عُرّفت في إعداد P2.2.

## 1. سبب فصل المسار

في P2.2، كانت خمسة أحزمة USGS مستعلم عنها. لكن G1 لم ينجح إلا لسلسلة واحدة من خمس في كل تمثيل زلزالي:

- تمثيل العدّ الشهري: سلسلة واحدة مؤهلة، وباقي أربع سلاسل لم تجتز G1.
- تمثيل فواصل الأحداث: سلسلة واحدة مؤهلة، وباقي أربع سلاسل لم تجتز G1.

إذن Bootstrap الزلزالي الذي ظهر في التقرير يصف Alaska–Aleutian فقط في هذين التمثيلين، ولا يعمم على الأحزمة الخمسة. في سلسلة الفواصل المؤهلة، أصدرت 998 من 999 إعادة توليد Markov إنذاراً واحداً أو أكثر؛ وفي العدّ الشهري أصدرت 612 من 999 إعادة توليد الإنذار. هذان الرقمان تشخيصان مشروطان، لا FPR زلزاليان مثبتان.

كذلك Stationary Bootstrap لفواصل الأحداث لا يمثل آلية توليد الزلازل تلقائياً. قد يحافظ على مقاطع محلية من الكتالوج، لكنه لا ينشئ نموذجاً صريحاً لتجمع الهزات التابعة أو تغير شدة الرصد أو اكتمال الكتالوج.

## 2. وحدة التحليل

يجب فصل نوعين من السلاسل وعدم الخلط بينهما:

### A. سلسلة الأحداث المعلّمة (Marked Point Process)

كل حدث يحتوي على:
- الوقت UTC بدقة المصدر.
- latitude/longitude/depth.
- magnitude.
- belt ID وsource event ID.
- عتبة الاستعلام والحد الأدنى للاكتمال المقدر `Mc(t, region)`.

### B. العدّ الشهري

`N_m` لكل شهر UTC داخل فترة استعلام مكتملة. الصفر مقبول فقط إذا كان الاستعلام كاملاً وكانت صلاحية الرصد مثبتة؛ لا يستبدل الصفر المفقود أو غير المتحقق منه بقيمة صفر.

### C. فواصل الأحداث

`Δt_i = t_i - t_{i-1}`، مع الاحتفاظ بالترتيب الزمني. لا يُعامل كل فاصل كعينة مستقلة؛ التتابع الزلزالي نفسه يخلق اعتماداً زمنياً ومكانياً.

## 3. متطلبات اكتمال الكتالوج قبل الملاءمة

لكل حزام ولكل فترة زمنية، سجّل:

1. حد اكتمال المقدار `Mc` وتغيره زمنياً ومكانياً.
2. توزيع المقدار واحتمال عدم رصد الأحداث الصغيرة.
3. تغييرات أجهزة الرصد والشبكات والتغطية الجغرافية.
4. انقطاعات الخدمة وتغيرات ingestion أو مراجعات الكتالوج.
5. إزالة التكرار بين event IDs وتوحيد إحداثيات/أوقات الأحداث.
6. حساسية النتائج عند عتبات M4.5 وM5.0 وM5.5 وM6.0، على أن تقرر صلاحية كل عتبة من تحليل اكتمال الكتالوج لا من نتائج المحرك.

لا يصح استخدام العتبة M4.5 كدليل على ثبات الاكتمال من 1980 إلى 2024 لجميع الأحزمة. لا تُملأ فجوات الرصد، ولا تدمج النوافذ الجغرافية دون تعريف مسبق.

## 4. عائلات null المرشحة

لا يُختار null بعد رؤية أي واحد منها يعطي إنذارات أقل. تسجل صلاحية كل نموذج وفشل ملاءمته.

### N0 — Homogeneous Poisson

مرجع baseline بسيط لمعدل ثابت داخل الحزام والفترة. مفيد كاختبار ضابط أولي فقط. إذا أظهر الزمن تغيراً في المعدل أو تجمّعاً زلزالياً، يُرفض كمرجع مناسب لذلك الحزام.

### N1 — Inhomogeneous Poisson

`λ(t, region)` يتغير وفق تصميم مسبق أو نموذج معدل بطيء، مع تجنب تسريب الأحداث المستقبلية إلى تقدير الشدة في backtest. مناسب كاختبار لعدّ شهري عند وجود تغير بطيء في الخلفية، لكنه لا يحاكي aftershock clustering بذاته.

### N2 — Hawkes / ETAS-like point process

النموذج الأساسي المقترح لاختبار التجمع الزلزالي. يضم:

- خلفية زلزالية `μ(x,y,t)`.
- kernel زمني للهزات التابعة من عائلة Omori–Utsu.
- kernel مكاني يعتمد المسافة.
- mark magnitude من توزيع Gutenberg–Richter بعد حد الاكتمال.
- productivity term يعتمد مقدار الحدث السابق.

يجب فرض شروط الاستقرارية/branching ratio وفحص قابلية تقدير المعلمات. لا يُقبل ETAS لمجرد أنه أكثر تعقيداً؛ يجب أن يجتاز اختبارات ملاءمة على بيانات تدريب فقط.

### N3 — Conditional time-rescaling

استخدم الزمن المتكامل للشدة التراكمية `τ_i = ∫ λ(t|H_t)dt` لفحص بواقي عملية الأحداث. إذا لم تتوافق البواقي مع Exp(1) أو أظهرت اعتماداً متبقياً، فالنموذج لا يصلح لتوليد null قبل إعادة المواصفة.

## 5. بروتوكول الملاءمة والتحقق

1. تقسيم زمني مسبق: نافذة ملاءمة، ثم نافذة تحقق خارج العينة، مع تقييم rolling-origin عندما تسمح أطوال البيانات.
2. الملاءمة منفصلة لكل حزام؛ لا تنقل معلمات حزام إلى آخر دون عقد نقل مبرر.
3. مقارنة N0/N1/N2 باستخدام تشخيصات الملاءمة لا أفضلية عدد الإنذارات.
4. فحص time-rescaling residuals، استقلال البواقي، توزيعات المقدار، clustering الزمني والمكاني، وعدد الأحداث في النوافذ.
5. فحص حساسية `Mc` وفترات الرصد وقيود الاستعلام.
6. إذا فشل نموذج معين في حزام محدد، تسجّل حالة `MODEL_NOT_FIT` ولا يُحسب null لذلك الحزام.

## 6. محاكاة null وتقييم الكاشف

بعد اعتماد عائلة null لكل حزام:

- 9,999 كتالوج محاكى لكل تركيبة رئيسية عندما تسمح كلفة الملاءمة؛ 999 حد أدنى استكشافي.
- الحفاظ على فترة الرصد الفعلية، المنطقة، حد المقدار، نظام العلامات، ومواصفات الاكتمال.
- تطبيق التحويل نفسه الذي سيستخدم في بيانات الاختبار: عدّ شهري أو فواصل زمنية؛ لا تغيير في الوحدات بين real وsimulated.
- تشغيل BreakDetectorV1 دون أي تعديل.
- تخزين سجل كل كتالوج محاكى: seed، المعلمات، عدد الأحداث، سلسلة الإدخال، الإنذارات، أوقات الكشف، count، SHA-256.
- عرض احتمال إنذار واحد أو أكثر، عدد الإنذارات لكل 1000 belt-year، توزيع زمن أول إنذار، وتوزيع أعداد الإنذارات. لا تختزل ذلك إلى نسبة واحدة.
- لا يُسمى هذا FPR نهائياً إلا عند وجود تصميم null موثق وملاءمة كافية واختبار حجم معلوم؛ وإلا يسمى `conditional null alarm probability`.

## 7. مقاييس الإبلاغ

لكل حزام ولكل null منفصل:

| المقياس | الغرض |
|---|---|
| Probability of ≥1 alert/catalog | احتمال ظهور إنذار في كتالوج كامل تحت null |
| Alerts / 1,000 belt-years | معدل إنذارات مطبّع بالزمن الفعلي |
| Count distribution | حجم الإنذارات لا مجرد وجودها |
| First-alert time distribution | تحيز الإنذار نحو بداية/نهاية فترة الرصد |
| Residual diagnostics | هل null يصف آلية الأحداث بالفعل؟ |
| Mc sensitivity | ثبات النتيجة إزاء اكتمال الكتالوج |
| Between-belt heterogeneity | منع التعميم من حزام واحد على خمسة |

لا تدمج النوافذ الخمس في معدل واحد قبل إظهار النتائج الفردية وتبرير أي تجميع هرمي.

## 8. شروط منع P2.3 الزلزالي

لا يسمح بالانتقال إلى استشعار/إنذار زلزالي أو أي ادعاء تنبؤي قبل:

1. تحديد `Mc(t, region)` لكل حزام.
2. وجود null point-process يجتاز فحوص الملاءمة.
3. اختبار حجم خارج العينة على كتالوجات محاكاة وبيانات holdout.
4. توثيق التغطية الزمنية وحدودها وأحداث الكتالوج المراجعة.
5. فصل detection delay بعد التغير عن warning lead قبله.
6. تكرار النتائج عند عدة عتبات مقدار دون انتقاء النتائج الملائمة.
7. حفظ كل الإصدارات والـmanifests والبصمات دون تعديل أرشيف Phase 1.

- هذا العقد لا يعدّل `BreakDetectorV1` أو عتباته.
