# P2-B — الدفعة الأولى لمنافسة الكواشف

## النطاق
مقارنة Parallel Fusion G/H/J/K/I مع أوضاع BreakDetectorV1: fast وmarkov_cusum وconsensus على 509 سلسلة اقتصادية: 51 Pink Sheet و458 GEM. لا تدخل تمثيلات USGS في هذه الدفعة.

## سلامة المدخلات
- المدخل المثبت هو prepared artifact من Actions run 45244943216، artifact 14857826243، SHA-256: c83f6e960296fbbdb687650a798959f08cb8d98db68de8ca713d7be278e824fe.
- يعاد جلب Pink Sheet داخل الذاكرة فقط، مع مطابقة SHA-256 المصدر والمرشحين. قيم GEM تقرأ من shards المثبتة ويعاد حساب candidate_sha256.
- يجب استعادة 509 معرفات فريدة بالضبط. أي اختلاف بصمة أو عدد يوقف التشغيل.
- 359 سلسلة مؤهلة فقط لفحص null الأولي: 48 Pink Sheet و311 GEM. الـ150 الباقية تدخل replay والحقن.

## القياس
- null: 99 stationary-bootstrap replicates لكل سلسلة مؤهلة، متوسط كتلة 12. تقاس احتمالية حدث واحد أو أكثر، والأحداث لكل replicate، والأحداث لكل 1,000 مشاهدة.
- injected breaks: حقن تحول دائم موجب وسالب بمقدار 3× MAD لأول 40 مشاهدة، عند 70% من طول كل سلسلة. تسجل الحساسية، الفائت، الإنذار قبل البداية، خطأ الاتجاه، ووسيط/المئين 90 لتأخير الكشف.
- تسجل الأحداث التاريخية المرصودة وصفياً؛ لا توجد ground-truth labels لتسميتها إنذارات كاذبة.

## No-lookahead
- مقاييس Parallel Fusion تستخدم الماضي فقط، وتُقارن الضربات وأحداث الدمج قبل cutoff بعد تغيير الذيل المستقبلي.
- يعاد تحليل BreakDetectorV1 على بادئة تنتهي عند detection_time لكل حدث. الأحداث التي لا تسمح أطوالها الدنيا بإعادة التشغيل تسجل unverifiable صراحة.
- يتحقق workflow من Git blob IDs لملفات BreakDetectorV1 دون تعديلها، ويشغل guard ضد أي تغيير في experiments/**.

## حدود الاستنتاج
احتمالات stationary bootstrap تشخيصات مشروطة وليست operational FPR. الحقن يحدد truth مضبوطة لقياس الحساسية والتأخير، ولا يثبت صحة التصنيف التاريخي. لا تتوفر vintages/available_at تاريخية لـPink Sheet وGEM؛ لذا يختبر no-lookahead سببية الخوارزمية داخل snapshot، لا ثبوت إتاحة كل قيمة في تاريخها الفعلي. لم تُعثر تطبيقات متعقبة لـFOCuS أو BOCPD أو R-FPOP في main-phase2، ولذلك لا تدعي هذه الدفعة مقارنتها.

لا تعديل لـexperiments/** أو structural_engine/isolated_break_detector_v1/** أو سجل الحوكمة.

## عقد إضافة الكواشف اللاحقة
تستخدم الدفعة الأولى الأذرع الحالية فقط، لكن محرك القياس لم يعد محصوراً في G/H/J/K/I. توجد واجهة `register_detector(name, runner, ...)` تسجل كاشفاً إضافياً مع بيانات وصفية قابلة للتسلسل JSON. يجب أن يعيد `runner` قائمة `hits`، وكل ضربة تتضمن `index` صحيحاً يمثل وقت إصدار الإنذار و`sign` يساوي `+1` أو `-1`، ويمكن تضمين `detector` اختيارياً. يمكن أيضاً إرجاع `events`، وكل حدث يتضمن `start_index` بوصفه أول وقت إصدار قابل للرصد و`sign`، مع `metadata` JSON اختيارياً. يحوّل المحول النتيجة إلى المخطط الموحد الذي تستخدمه مقارنة null والحقن والتجميع. عند تفعيل التدقيق السببي، يعاد تشغيل الكاشف على بادئة تنتهي عند كل ضربة وكل حدث للتحقق من ظهورهما دون الاطلاع على الذيل. تبقى أسماء الأذرع الحالية مطلوبة، لكن الاختبارات لا تمنع تسجيل أذرع إضافية.

الأسماء التالية مقبولة عبر الواجهة نفسها، دون الادعاء بأنها مطبقة أو داخلة في هذه الدفعة: `FOCuS`، `R-FPOP`، `BOCPD`، `Post-Quiet Huber`، `Bartlett LRV`. تُحمّل وحدات التنفيذ اللاحقة صراحة عبر `--plugin-module package.module` أو المتغير `P2B_DETECTOR_PLUGIN_MODULES`؛ وتستدعي كل وحدة `register_detector` عند الاستيراد. لكل خوارزمية لاحقة يلزم تنفيذ مستقل واختبار تحقق قبل تسجيلها في المنافسة. لا تُضاف أسماء مستقبلية إلى نتائج هذه الدفعة ما لم تسجل خوارزمية فعلية.
