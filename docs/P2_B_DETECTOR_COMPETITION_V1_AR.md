# P2-B — الدفعة الثانية: منافسة خمسة كواشف مستقلة

## قرار التنفيذ
تعتمد هذه الدفعة خطي الأساس المجمدين فقط: `A_FAST` و`A_CONSENSUS`. تدخل خمسة كواشف مستقلة في المنافسة: `FOCuS` و`R-FPOP` و`BOCPD` و`Post-Quiet Huber` و`Bartlett LRV`.

لا تدخل Markov CUSUM أو Parallel Fusion G/H/J/K/I في هذه المنافسة. لا تعدّل ملفات `experiments/**` أو `structural_engine/isolated_break_detector_v1/**`.

## تعريف الخوارزميات وحدود المطابقة
- FOCuS: تطبيق مرشح مستوحى من المسح الوظيفي online متعدد النوافذ، مع مجموعة نوافذ محدودة. لا يدّعي هذا الإصدار المطابقة المرجعية لكل تفاصيل FOCuS المنشورة.
- R-FPOP: تطبيق مرشح مستوحى من segmentation وظيفي robust مع مجموعة بدايات bounded وعقوبة معلنة. لا يدّعي المطابقة المرجعية لخوارزمية R-FPOP أو تنفيذها الأصلي.
- BOCPD: نموذج Bayesian online run-length باحتمال تنبؤ Gaussian وhazard ثابت، مع قص run-length إلى 256.
- Post-Quiet Huber: بواقي robust مقصوصة عند 1.5 MAD-sigma واختبار run موقّع.
- Bartlett LRV: بواقي studentized باستخدام long-run variance وBartlett kernel على نافذة ماضية.

تظهر هذه القيود في metadata لكل كاشف. لا يجوز وصف FOCuS أو R-FPOP بأنهما paper-conformant قبل مطابقة معادلات الورقة واختبارات مرجعية مستقلة.

## عقد التشغيل
- أول 40 مشاهدة للمعايرة فقط؛ لا يسمح بأي hit أو event يبدأ قبل الفهرس 40.
- إذا كان MAD لأول 40 مشاهدة صفراً، تكون النتيجة `ABSTAIN / ZERO_QUIET_SCALE` لكل الأذرع؛ لا يصدر الإنذار من مقياس غير معرّف.
- تدقيق السببية: إعادة تشغيل كل قرار على بادئته المنتهية عند زمن القرار، وتغيير الذيل المستقبلي دون تغيير قرارات ما قبله.
- المقارنة على 509 سلسلة مثبتة: 51 Pink Sheet و458 GEM، مع 359 سلسلة null-eligible كما في manifest المصدر.
- أربعة shards مستقلة متوازية، وكل runner يعمل بـ4 workers. بذور bootstrap تظل مشتقة من معرف السلسلة.
- يبقى بروتوكول التجميع والتحقق من جميع الشرائح والـ manifest كما هو.

## القياس
تُقاس الأحداث المرصودة وصفياً، وتُقاس null عبر stationary bootstrap، وتُقاس الحساسية والتأخير وخطأ الاتجاه عبر الحقن الموجب والسالب. نتائج bootstrap تشخيصات مشروطة وليست معدلات إنذار تشغيلي حقيقية. لا توجد labels محكّمة للأحداث التاريخية.

## بوابة القبول
لا دمج قبل نجاح الاختبارات، اكتمال الشرائح الأربع، تطابق manifest، غياب بيانات أو معرفات ناقصة، ومرور causal replay / suffix mutation لكل arm. يجب مراجعة أداء كل خوارزمية وأعداد ABSTAIN قبل اختيار المرشح، ولا يضمن الفوز مسبقاً.
